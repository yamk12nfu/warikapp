## 0. 前提

Phase 0〜9 は完了し、**https://warikapp.yamk12nfu.com** で本番稼働中。
機能はひととおり動く。**足りていないのは視覚的な仕上げだけ。**

要件定義書(`docs/requirements.md`)に**視覚デザインの要件は無い**。Tailwind の選定理由も
「スマホファーストUIを**高速に構築**」で、見た目は意図的に後回しにしてあった。

ただし要件2.1に「パートナーB = 一般的なスマホユーザー。**操作は直感的に完結する必要がある**」、
US-010に「外出先で使うため、スマホで快適に操作したい」とあるため、**直感性の観点では要件に紐づく**。

## 1. 現状の観測(ホーム画面 / 375×812)

本番のホーム画面(世帯作成直後・支出0件)を実機サイズで見て気づいた点。優先度順。

| # | 問題 | 根拠 |
|---|---|---|
| 1 | **主役と脇役が逆** | 「+ レシート」が枠線のみ、「+ 手入力」が塗りつぶし。このアプリの主機能はレシート撮影(F-003)で、手入力(F-005)はフォールバック |
| 2 | **未精算差額が弱い** | US-004「ホーム画面に『誰が誰にいくら』が常時表示される」= このアプリで最も重要な数字。いまは薄いグレーの箱の中で小さい |

| 5 | **色が無い** | グレースケール+青リンク1色。金額の方向・未確定バッジ・警告が同じ重みに見える |
| 6 | **画面名が毎回 h1 で「warikapp」** | 一等地を使って情報量がゼロ |

## 2. 守るべき制約

### 触ってはいけないもの

- **金額と日付の表示は `lib/format.ts` の `formatYen` / `formatDateLabel` を通す**(全画面で統一済み)
- **`components/ExpenseEditor.tsx` の負担区分チップの操作体系**: タップで 折半 → 自分 → 相手 → 折半 の循環、「%」でカスタム。
  要件F-004の「1レシート20品目を1分以内に片手で仕分け」がここに懸かっている。**見た目は変えてよいが、タップ回数を増やさない**
- **`ExpenseEditor` に数量の入力欄を足さない**(Phase 8の設計前提。数量は品目名に畳み込んで `quantity` は常に1)
- 画面の認証ガード: `currentMember` で世帯所属を確かめてから世帯データのqueryを呼ぶ(未所属は `/setup` へ)。
  ローディング中の `読み込み中…` は**Convexのqueryが解決するまでの状態**で、消すと未所属判定が壊れる

### lint の制約(Phase 6で踏んだ)

- `react-hooks/purity`: レンダー中の `Date.now()` はエラー。時刻判定は `setTimeout` のコールバックへ
- `react-hooks/set-state-in-effect`: effect本体での `setState` はエラー。`window` 依存の値は `useSyncExternalStore`
- 実例: `components/InviteCodeCard.tsx`

## 3. 性能の実測(デザイン判断に効く)

本番ビルド + localhost、キャッシュ温の状態:

| 画面 | FCP | LCP |
|---|---|---|
| ホーム | 68ms | **1,652ms** |
| 精算 | 72ms | **1,820ms** |
| 精算履歴 | 52ms | **1,596ms** |

- 初回訪問(JSチャンク未キャッシュ)は **2,764ms** で、**要件5.1の「主要画面の初期表示2秒以内」を超えている**
- 内訳の大半は **Clerkのクライアント初期化(約1.5秒)**。HTMLのTTFBは24ms、FCPは50〜70msで出ている
- **つまり「データが出るまで」が遅い。ローディング状態の見せ方はデザイン上の重要事項**
  (スケルトンか、楽観的な骨組みか、Clerk初期化中に何を出すか)
- 実機・4G での実測はまだ。デザイン着手前に測る価値がある

## 4. 決めるべきこと

1. **方向性**: このアプリの性格をどう見せるか(家計簿的な実用一辺倒 / 二人の生活の記録 / ミニマル 等)
2. **アクセントカラー**: 1色決めて、金額の方向・未確定バッジ・警告・破壊的操作を体系化する
3. **ナビゲーション構造**: 下部固定タブ(ホーム / 精算 / 設定)にするか、現状の本文内リンクを整えるか
4. **ローディングの見せ方**: 上記のとおり1.5秒はClerk待ちで避けられない。ここをどう繕うか
5. **空状態**: いまは「未精算の支出はまだありません」の一行のみ
6. **ダークモード**: 現在 `prefers-color-scheme` で自動。本番はダークで見ている

## 5. スコープ外

- 同時編集の競合(F-006): `ExpenseEditor` が `initialValue` をマウント時にしか読まないため、
  編集画面を開いたまま相手が保存すると**古いフォームのまま上書きされる**
- 世帯からの退出(TBD-007)の導線が無い
- `releaseUpload` がUIから到達できない(画像差し替えのUIが無い)
- 置き去りアップロードの掃除(TBD-002)は運用開始後に判断
