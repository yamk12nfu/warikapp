warikapp のコードを読み始める人へ

warikappは画面で品目を仕分け、サーバーで世帯ごとの精算を記録する

結論: 同棲カップル向けのレシート割り勘アプリ。画面は入力と確認を担当し、サーバーが世帯別に支出を保存して、立て替えの差額を計算する。
  1. Next.js が画面、Convex が保存と計算、Clerk が本人確認を担当する。
  2. AIが読み取った支出は下書きになり、人が確定した品目を精算額に反映する。
  3. 画面は保存先に直接つながり、外部AIからの照会は専用の窓口を経由する。

画面・保存・AIの担当

Next.js はページを作る仕組みで、Vercel はその配信サービス。ブラウザでは React が画面の表示や入力を担当する。Convex はデータ保存・画像保存・サーバー処理をまとめて担当する。

画面は Convex に直接つながり、データの変更を受け取って表示を更新する。Clerk はログインを扱い、本人確認の結果を Convex に渡す。Convex は本人と世帯への所属を確認してからデータを返す。

Gemini は既定のレシート読取AIで、設定によって Claude に切り替えられる。AIを呼ぶ処理と、その接続に使う秘密の文字列は Convex 側に置く。

レシート読取と確定の境目

画像を圧縮して送信し、その画像がどの世帯のものかを登録する。AIが品目を抽出すると、画面が保存処理を呼び、下書きを自動保存する。画面を離れても下書きは残り、金額が変わりうるため精算差額からは除く。

人が品目・支払者・負担割合を確認し、確認済みとして残す操作が確定保存。この支出が精算対象になる。税や値引きによる合計差額は、可能な場合に品目へ配分する。手入力も、同じ編集部品から支出を保存する。

世帯に属する支出と精算

保存先は世帯・参加者・招待・支出・精算・画像と世帯の対応を持つ6テーブル。テーブルは同じ種類の記録を集める場所で、coupleId が所属する世帯を示す。品目は支出内の配列 items、つまり品目を順に並べたデータにまとめる。画像本体は別の画像保存領域に置く。

精算額は、双方が相手のために立て替えた金額の差。品目ごとに負担割合を掛けて四捨五入し、合算する。同じ計算処理を画面とサーバーが共有するため、内訳表示と精算の計算方法がそろう。

精算時は金額を計算し直し、確認画面の金額・向き・件数と照合する。精算記録の作成と支出への関連付けをまとめて更新するため、途中の状態が残らない。精算済みの支出は編集できず、直近の精算だけ取り消せる。

外部AIは専用窓口から支出を照会

MCP は外部のAIアプリが、このアプリの機能を呼ぶ接続方式。未精算差額・支出一覧・月次集計・品目内訳を、読み取り専用の4ツールで公開する。レシート読取AIとは別の経路で、支出の追加や精算実行はできない。

Next.js の /mcp が、Clerk の OAuth（外部サービス向け認証）で本人を確認する。本人IDは利用者を識別する値で、確認済みの値だけを Convex に渡す。

内部キーは、サーバー間の接続を確認する秘密の文字列。Convex はこのキーを確かめ、本人IDから所属世帯を照合する。外部AIから届く本人確認用の認証トークンは、Convex に転送しない。照会結果にも画像へのリンクを含めない。

変更したい機能からコードをたどる

app はページと画面、components は共有する画面部品、convex は保存と権限確認を担う。lib は金額計算や画像処理などの共通処理を置く場所。画面の操作から呼び出し先を追うと、入力・検証・保存のつながりが分かる。

通常のページはログインを確認してから、操作用の画面ファイルを呼ぶ。品目の入力部品は、レシート・手入力・編集で共用する。配信設定は、Convex の更新と Next.js の画面を配信する準備を一つのコマンドで行う。
